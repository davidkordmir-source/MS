# Terrain Studio 0.2.0

نرم‌افزار دسکتاپ مستقل از ArcGIS Pro برای استخراج پلیگون از DEM/DSM بر اساس محدوده مکانی و ارتفاع.

## اجرا در ویندوز

Windows 10/11 نسخه ۶۴ بیتی پیشنهاد می‌شود. فایل `TerrainPolygon-Setup.exe` نصاب آفلاین برنامه است؛ آن را با فلش به سیستم مقصد منتقل و دوبارکلیک کنید. برنامه از منوی Start یا میانبر دسکتاپ اجرا می‌شود. سیستم مقصد به اینترنت، Python یا ArcGIS نیاز ندارد. نصاب برای کاربر جاری نصب می‌شود و حذف آن از Settings → Apps ممکن است. این نسخه پردازش CPU دارد؛ CUDA در نصاب استاندارد نیست.

این بسته با Windows Python و PyInstaller تحت Wine 10 ساخته شده است. آزمون‌های پردازش و آزمون خود EXE در Wine انجام شده‌اند؛ آزمایش روی ویندوز واقعی و GPU واقعی انجام نشده است. فایل اجرایی امضای دیجیتال تجاری ندارد.

برای ساخت: Python 3.12 نسخه x64 و NSIS 3 را نصب کنید، سپس در PowerShell از ریشه مخزن اجرا کنید:

```powershell
powershell -ExecutionPolicy Bypass -File packaging/build.ps1
```

همچنین workflow با نام **Windows installer** در GitHub Actions روی push به main، pull request یا اجرای دستی ساخته می‌شود. پس از موفقیت، نصاب را از artifact با نام `TerrainPolygon-Windows-x64` دریافت کنید. اجرا شدن workflow وابسته به ارسال این تغییرات به GitHub است.

برای اجرای مستقیم از سورس:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_app.py
```

## مراحل استفاده

1. شیپ فایل نقطه یا پلیگون را انتخاب کنید. فایل‌های همراه `.shx`، `.dbf` و اطلاعات مختصات `.prj` باید کنار آن باشند. لایه خطی یا مخلوط پشتیبانی نمی‌شود.
2. برای نقاط، شعاع بافر را به **متر** وارد کنید. برای پلیگون‌ها همان محدوده استفاده می‌شود و شعاع نادیده گرفته می‌شود. همه عوارض ورودی پردازش می‌شوند.
3. یک DEM/DSM تک‌باند مانند GeoTIFF با CRS مشخص انتخاب کنید. تبدیل CRS ورودی به CRS رستر خودکار است.
4. شرط ارتفاع را انتخاب کنید: بین دو مقدار (شامل هر دو حد)، بیشتر از حد پایین (بدون خود حد)، یا کمتر از حد بالا (بدون خود حد).
5. مسیر جدید با پسوند `.shp` تعیین کنید؛ فایل‌های موجود بازنویسی نمی‌شوند.
6. پردازش را اجرا کنید. رابط هنگام پردازش فعال می‌ماند و وضعیت یا خطا را نمایش می‌دهد. بستن برنامه حین پردازش مسدود است.

خروجی شامل `.shp`، `.shx`، `.dbf`، `.prj` و `.cpg` است. برای جابه‌جایی خروجی، همه این فایل‌ها را با هم منتقل کنید.

| فیلد | مفهوم |
|---|---|
| obj_id | شناسه ناحیه متصل |
| elev_min | کمترین ارتفاع پیکسل‌های ناحیه |
| elev_max | بیشترین ارتفاع پیکسل‌های ناحیه |
| elev_mean | میانگین ارتفاع پیکسل‌های ناحیه |
| pix_count | تعداد پیکسل‌ها |
| z_unit | واحد عمودی از متادیتای رستر، یا unknown |

## معنای ارتفاع و محدودیت‌ها

این ابزار معادل یک گردش کار Mask → Elevation filter → Connected raster regions → Polygon است. هر مجموعه پیکسل متصل از ضلع (۴ همسایه) یک عارضه خروجی است؛ تماس گوشه‌ای نواحی را یکی نمی‌کند. حفره‌ها حفظ می‌شوند. مرزها مطابق شبکه رستر هستند و برای ورود به محدوده از مرکز پیکسل استفاده می‌شود؛ بنابراین برش مرز پلیگون دقت برداری کامل ندارد. NoData، NaN و بی‌نهایت حذف می‌شوند. Scale و Offset رستر قبل از اعمال شرط ارتفاع لحاظ می‌شوند.

ارتفاع‌ها در واحد عمودی داده ورودی هستند؛ برنامه واحد افقی CRS را به عنوان واحد ارتفاع فرض نمی‌کند و تبدیل واحد عمودی/دیتوم انجام نمی‌دهد. اگر واحد `unknown` بود، آن را از مشخصات منبع بررسی کنید. DEM معمولاً ارتفاع زمین و DSM ارتفاع سطح شامل ساختمان و درخت را نسبت به دیتوم عمودی نشان می‌دهد. **ارتفاع ساختمان از پای آن از یک DSM به‌تنهایی قابل استخراج نیست**؛ برای آن باید DTM هم‌مرجع از DSM کم شود (این نسخه این محاسبه را ندارد). این ابزار طبقه‌بندی ساختمان/کوه و تفکیک اشیای چسبیده به یکدیگر را انجام نمی‌دهد.

رسترهای چرخیده یا south-up در حافظه به شبکه north-up تبدیل می‌شوند (نمونه‌برداری نزدیک‌ترین همسایه). باند ارتفاع را در رابط انتخاب کنید.

برای کنترل حافظه، محدوده برش حداکثر ۴۰ میلیون سلول مجاز است. برای داده بزرگ‌تر محدوده را کوچک یا رستر را resample کنید. تعداد زیاد عوارض یا پلیگون‌های بسیار پیچیده زمان و حافظه بیشتری می‌طلبد. محدودیت‌های ذاتی Shapefile از جمله اندازه فایل و دقت DBF برقرار هستند.

## CPU و GPU

خواندن GDAL با تعداد thread انتخابی و محاسبه آمار عوارض با threadهای CPU انجام می‌شود. تبدیل رستر به پلیگون در GDAL روی CPU انجام می‌شود. مصرف صددرصد همه هسته‌ها یا GPU قابل تضمین نیست و به I/O و شکل داده بستگی دارد.

CUDA اختیاری است: برای اجرای سورس، در محیط دارای NVIDIA و درایور سازگار با CUDA 12 می‌توانید `cupy-cuda12x` را جداگانه نصب کنید. گزینه GPU فیلتر ارتفاع را روی CUDA اجرا می‌کند و در نبود آن به CPU برمی‌گردد؛ نتیجه یکسان است. نصاب استاندارد وابستگی CUDA را شامل نمی‌شود و مسیر CPU را استفاده می‌کند. برای ساخت اختصاصی GPU باید CuPy و کتابخانه‌های لازم در بسته‌بندی Windows اضافه و روی سخت‌افزار مقصد تست شوند. AMD/Intel GPU در این نسخه شتاب‌دهی نمی‌شوند.

## تست

```bash
.venv/bin/python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen .venv/bin/python -c "from PySide6.QtWidgets import QApplication; from terrain_export.gui import Window; a=QApplication([]); w=Window(); w.show(); a.processEvents(); w.close()"
```

تست‌های موتور با DEM و Shapefile واقعی موقت اجرا می‌شوند و شامل اتصال نواحی، آمار ارتفاع، NoData، شروط مرزی، خروجی خالی، عدم بازنویسی و بافر متری در مختصات جغرافیایی هستند. تست GPU بدون سخت‌افزار تنها مسیر fallback را بررسی می‌کند. آزمایش روی Windows واقعی و CUDA واقعی همچنان لازم است.

برای لایه بدون CRS تنها در صورت اطلاع از سیستم مختصات واقعی، کد EPSG صحیح را در فیلد CRS جایگزین وارد کنید. نام‌های خروجی تکراری در GUI با شماره جدید ذخیره می‌شوند. خطاها در LOCALAPPDATA/TerrainPolygon/logs/application.log ثبت می‌شوند و دکمه ذخیره گزارش هم وجود دارد.
