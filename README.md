# Terrain Studio 0.3.0 — DEM / DSM → Polygon Shapefile

ورودی‌ها فایل‌های خود کاربر هستند؛ هیچ داده‌ای از اینترنت گرفته نمی‌شود.

1. پلیگون محدوده را به صورت Shapefile با فایل‌های همراه SHX، DBF و PRJ انتخاب کنید.
2. DEM و DSM را در مسیرهای جدا انتخاب کنید و باند ارتفاع را مشخص کنید.
3. **مبنای ارتفاع را صریح انتخاب کنید**: مقدار خود DEM، مقدار خود DSM، یا ارتفاع از زمین (`DSM − DEM`).
4. اگر متادیتای واحد عمودی وجود ندارد، مشخص کنید داده شما متر است یا فوت. آستانه‌ها و خروجی جدید به متر هستند. واحدهای شناخته‌شده هر رستر جداگانه تبدیل می‌شوند.
5. مثلاً شرط «بیشتر از حد پایین» و مقدار **۳۰** را بگذارید. خود ۳۰ شامل «بیشتر از» نیست.
6. «بررسی محدوده و پیش‌نمایش واقعی» را بزنید: مرز زرد پلیگون شماست، فیروزه‌ای پیکسل‌های منطبق داخل همان محدوده است. طول/عرض مرکز و CRS خروجی هم نمایش داده می‌شوند.
7. خروجی SHP را تعیین و استخراج کنید. همه فایل‌های خروجی را با هم نگه دارید.

## قرارداد مکانی

- خروجی **در CRS پلیگون ورودی** است و PRJ از همان CRS نوشته می‌شود، نه CRS متفاوت رستر.
- هیچ CRS حدس زده نمی‌شود. CRS تعریف‌شده قابل جایگزینی با یک EPSG دیگر نیست؛ تغییر برچسب CRS، بازپروژکت کردن نیست و می‌تواند لایه را جابه‌جا کند. برای لایه بدون CRS فقط کد صحیح منبع قابل معرفی است.
- ابتدا پیکسل‌های مطابق شرط انتخاب و نواحی متصل چهارهمسایه استخراج می‌شوند؛ سپس هندسه دقیقاً با **پلیگون اصلی کاربر** قطع می‌شود. حفره‌ها و مرز غیرمستطیلی محدوده حفظ می‌شوند. مرز داخلی نواحی طبق شبکه رستر است؛ ساختمان به طور معنایی تشخیص داده نمی‌شود.
- قبل از تحویل، برنامه فایل نوشته‌شده را باز می‌کند و CRS و باقی‌نماندن هندسه بیرون محدوده را بررسی می‌کند.
- پیش‌نمایش از همان مسیر پردازش و همان محدوده و مبنای ارتفاع تهیه می‌شود؛ به دلیل نمونه‌برداری نمایش، جزئیات آن تقریبی است. پیش‌نمایش، کل رستر نامرتبط با محدوده نیست.
- در حالت اختلاف، شبکه DSM مبناست. DEM با بازپروژکشن و نمونه‌برداری bilinear به شبکه DSM هم‌تراز می‌شود. NoData هر دو رستر حذف می‌شود. DEM و DSM باید از یک مرجع عمودی و تاریخ/کیفیت مناسب باشند؛ برنامه اختلاف دیتوم عمودی یا خطای نقشه‌برداری منبع را اصلاح نمی‌کند.
- محدوده‌هایی که رستر آنها را پوشش نمی‌دهد خروجی ندارند. خروجی شامل بخشی است که داده معتبر دارد. رستر چرخیده به شبکه north-up تبدیل می‌شود.

## جدول خروجی و گزارش

`obj_id` شناسه ناحیه، `elev_min`، `elev_max` و `elev_mean` آمار ارتفاع، `pix_count` تعداد سلول‌های مؤثر، `z_unit` واحد و `h_ref` مبنا (`DEM`، `DSM` یا `DSM-DEM`) هستند.
پیکسل‌های مرزی که بخشی از مساحتشان در محدوده است مشارکت می‌کنند؛ آمار میانگین ساده سلول‌هاست، نه میانگین وزنی مساحت.
فایل JSON کنار SHP، CRS، bounds، مبنای ارتفاع و شرط اعمال‌شده را ثبت می‌کند تا خروجی قابل ردیابی باشد.

## نصب و تست

نصاب `TerrainStudio-0.3.0-Setup.exe` برای Windows 10/11 x64 است. سیستم مقصد به اینترنت، Python یا ArcGIS نیاز ندارد. این بسته CPU است؛ CUDA شامل نمی‌شود.
برای آزمایش داخلی، دکمه داده نمونه را بزنید: DEM و DSM مصنوعی با دو ناحیه ارتفاع از زمین بیش از ۳۰ متر همراه برنامه‌اند.

ساخت از سورس روی Windows با Python 3.12 و NSIS 3:

```powershell
powershell -ExecutionPolicy Bypass -File packaging/build.ps1
```

اجرای سورس:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_app.py
```

تست: `python -m unittest discover -s tests -v`
تست EXE: `TerrainPolygon.exe --self-test report.json`

تست‌های مکانی شامل تهران، نیویورک، توکیو، نایروبی و ریو با مختصات مصنوعی معلوم هستند؛ هندسه خروجی با اجتماع مستقل سلول‌های بالای ۳۰ متر و تقاطع پلیگون دارای حفره مقایسه می‌شود. اختلاف CRS بین DEM و DSM، تبدیل فوت به متر، NoData، PRJ و مختصات عددی هم بررسی می‌شوند.
فایل اجرایی با Windows Python / PyInstaller تحت Wine ساخته می‌شود. تست روی ویندوز واقعی و داده‌های واقعی گزارش‌شده کاربر انجام نشده است. هیچ ادعایی درباره بازتولید خطای قبلی بدون دریافت داده‌های آن نمی‌شود.

محدودیت باقی‌مانده: حداکثر ۴۰ میلیون سلول در محدوده برش؛ دیتاست بزرگ‌تر باید محدود یا resample شود. تغییرات مرز طبق اندازه پیکسل طبیعی است؛ از یک رستر کم‌تفکیک نمی‌توان مرز واقعی عوارض را با دقت برداری استخراج کرد.
