# Terrain Studio 0.5.0 — DEM / DSM → یک لایه Polygon Shapefile

یک فایل **DEM یا DSM** وارد کنید، روی نقشه خود فایل محدوده بکشید و ارتفاعی مثل «بیشتر از ۳۰ متر» تعیین کنید. همه نواحی جدا در **یک شیپ‌فایل واحد** ذخیره می‌شوند؛ هر پلیگون شناسه و آمار ارتفاع مستقل دارد.

مرجع ارتفاع فقط **عدد ثبت‌شده در همان فایل ورودی** است. برنامه ارتفاع زمین یا مرجع دیگری را از آن کم نمی‌کند. نوع DEM یا DSM در جدول و گزارش خروجی ثبت می‌شود. Scale و Offset فایل و واحد عمودی معتبر خوانده می‌شوند؛ آستانه و آمار خروجی به متر هستند. اگر واحد عمودی در فایل نیست، متر یا فوت بودن داده را خودتان مشخص کنید.

## استفاده در Windows 10/11 x64

نصاب نسخه جدید: `downloads/TerrainStudio-0.5.0-Setup.exe`.
پس از نصب، برای اجرا به Python، ArcGIS یا اینترنت نیاز نیست.

1. فایل DEM یا DSM و باند ارتفاع را انتخاب کنید؛ نوع مدل را مشخص کنید.
2. نقشه خود رستر نمایش داده می‌شود. با چرخ ماوس زوم و با کشیدن نقشه جابه‌جا شوید.
3. «رسم محدوده» را بزنید و برای رأس‌های پلیگون کلیک کنید. با «پایان رسم»، Enter یا راست‌کلیک پلیگون را ببندید. Backspace آخرین رأس را حذف می‌کند؛ Esc رسم را لغو می‌کند.
4. حد ارتفاع، مثلاً **بیشتر از ۳۰ متر**، را وارد کنید. خود ۳۰ شامل شرط «بیشتر از» نیست. برگه «پیش‌نمایش شرط ارتفاع» نواحی منطبق داخل محدوده را نشان می‌دهد.
5. مسیر خروجی را انتخاب و «شروع استخراج» را بزنید. برای محدوده آماده می‌توانید حالت «شیپ‌فایل محدوده آماده» را انتخاب کنید.
6. همه فایل‌های هم‌نام SHP، SHX، DBF، PRJ و CPG را کنار هم نگه دارید؛ اینها اجزای **یک لایه** هستند، نه خروجی جدا برای هر جسم. فایل JSON هم گزارش پردازش است.


## اصلاحات رابط و سرعت در ۰.۵.۰

- اسکرول روی فیلدها و فهرست‌ها فقط فرم را جابه‌جا می‌کند و مقدار پارامتر را تغییر نمی‌دهد؛ کلیک و صفحه‌کلید همچنان فعال‌اند.
- شرط به صورت «ارتفاع عوارض از ۳۰ متر بالاتر باشد» یا «پایین‌تر باشد» نمایش داده می‌شود. تغییر جهت شرط، عدد واردشده را حفظ می‌کند.
- هر دو نمای نقشه و پیش‌نمایش خروجی زوم و جابه‌جایی دارند. چرخ ماوس و دکمه‌های + و − برای زوم هستند. پس از زوم، فقط پنجره قابل مشاهده از رستر اصلی با جزئیات بیشتر در پس‌زمینه خوانده می‌شود؛ مرز و مختصات محدوده تغییر نمی‌کند.
- زوم نرم، نمایش تدریجی جزئیات، بازخورد متحرک دکمه‌ها، رنگ‌بندی ارتفاع و صفحه شروع متحرک اضافه شده‌اند. لوگوی اختصاصی روی برنامه، نوار وظیفه، میانبر دسکتاپ و نصاب قرار دارد.
- خواندن قطعه‌ها با پیش‌خوانی محدود و محاسبه آمار با رشته‌های CPU انجام می‌شود. حالت خودکار، برای قطعه‌های بزرگ، CPU و GPU موجود را با احتساب انتقال داده مقایسه می‌کند؛ اگر GPU سریع‌تر نباشد، CPU انتخاب می‌شود.
- GPU محاسباتی به درایور OpenCL سازگار نیاز دارد و با GPUهای پشتیبانی‌شده NVIDIA، AMD یا Intel قابل استفاده است. کتابخانه برنامه در نصاب وجود دارد؛ در نبود دستگاه یا خطای درایور، CPU ادامه می‌دهد. هیچ CUDA Toolkit جداگانه‌ای برای این مسیر لازم نیست.
- رندر نقشه در صورت امکان از OpenGL کارت گرافیک استفاده می‌کند و در صورت نامعتبر بودن زمینه یا خالی‌بودن تصویر رندرشده به رندر سازگار CPU برمی‌گردد. ساخت پلیگون و نوشتن Shapefile همچنان بخشی از کار CPU هستند؛ افزایش سرعت ثابت یا پردازش کامل روی GPU ادعا نمی‌شود.

## جدول خروجی

| فیلد | معنی |
|---|---|
| `obj_id` | شناسه مستقل پلیگون |
| `elev_min` | کمترین ارتفاع داده ورودی در این پلیگون، به متر |
| `elev_max` | بیشترین ارتفاع داده ورودی در این پلیگون، به متر |
| `elev_mean` | میانگین ارتفاع داده ورودی در این پلیگون، به متر |
| `pix_count` | تعداد پیکسل‌های مؤثر |
| `z_unit` | واحد ارتفاع (`m`) |
| `h_ref` | مدل مرجع (`DEM` یا `DSM`) |

اگر ارتفاع سطح یک جسم متغیر باشد، یک عدد ارتفاع یکتا ندارد؛ حداقل، حداکثر و میانگین آن جدا ثبت می‌شوند. میانگین، میانگین ساده سلول‌های دارای تقاطع با پلیگون است، نه میانگین وزنی مساحت.

## مرز و مختصات

- هر ناحیه چهارهمسایه متصل بالاتر از آستانه یک ناحیه استخراج است. اگر برش محدوده آن را به چند بخش جدا تقسیم کند، هر بخش رکورد مستقل می‌گیرد. همه رکوردها داخل همان یک لایه ذخیره می‌شوند.
- مرز بر اساس سلول‌های رستر، با برش دقیق به پلیگون انتخاب‌شده است. حفره‌ها حفظ می‌شوند. صاف‌سازی یا تغییر مصنوعی شکل انجام نمی‌شود.
- **تشخیص معنایی ساختمان انجام نمی‌شود.** دو جسم چسبیده که در رستر یک ناحیه متصل تشکیل می‌دهند ممکن است یک پلیگون شوند. از DEM یا DSM کم‌تفکیک، مرز برداری دقیق‌تر از پیکسل یا ساختمان غایب از داده ساخته نمی‌شود.
- خروجی محدوده رسم‌شده در CRS رستر است. خروجی محدوده SHP آماده در CRS همان محدوده است. CRS حدس زده یا بدون بازپروژکشن عوض نمی‌شود.
- پیش‌نمایش برای نمایش نمونه‌برداری می‌شود؛ استخراج از تفکیک اصلی داده است. NoData حذف می‌شود و فقط بخش دارای داده معتبر خروجی دارد.
- پردازش ارتفاع قطعه‌ای و با فایل موقت انجام می‌شود؛ سقف قبلی ۴۰ میلیون سلول برداشته شده است. اتصال نواحی در مرز قطعه‌ها حفظ می‌شود. برای داده بزرگ فضای خالی دیسک و زمان کافی لازم است؛ پیچیدگی هندسه و محدودیت ۲ گیگابایتی اجزای Shapefile همچنان مهم‌اند.
- خروجی پیش از تحویل دوباره باز و از نظر CRS، اعتبار هندسه و باقی‌نماندن هندسه بیرون محدوده بررسی می‌شود. فایل موجود بازنویسی نمی‌شود؛ رابط نام جدید پیشنهاد می‌کند.

## اجرای سورس و ساخت

Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run_app.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

ساخت نصاب روی Windows با Python 3.12 و NSIS 3.11 یا جدیدتر (نصاب x64):

```powershell
powershell -ExecutionPolicy Bypass -File packaging/build.ps1
```

در محیط Linux بدون نمایشگر:

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen .venv/bin/python run_app.py --self-test /tmp/terrain-selftest.json
```

برای نتایج واقعی همین نسخه، `downloads/TEST-RESULTS.txt` را بخوانید. تست با داده مصنوعی و Wine جای آزمایش روی داده واقعی کاربر و ویندوز واقعی را نمی‌گیرد.
